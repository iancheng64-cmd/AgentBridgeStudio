# 安裝 AgentBridge Studio 0.5.5

支援 Apple Silicon（M 系列）的 Mac。安裝包最低設定為 macOS 13；實際測試系統列於 RELEASE_ACCEPTANCE.md。Intel Mac 不適用本檔案。

## 安裝

開啟 DMG，把 AgentBridge Studio 拖入 Applications，再從「應用程式」開啟。覆蓋舊版前先退出舊版 App。聊天、檔案庫及連線設定存在自己的使用者資料目錄，DMG 不含任何人的設定或帳號。

未公證版下載後可能被 macOS 攔下（提示已損毀或無法驗證開發者）：
- 終端機一鍵解除隔離（推薦）：`xattr -cr "/Applications/AgentBridge Studio.app"`
- 或至「系統設定 → 隱私權與安全性」按系統提供的「仍要打開」。不需關閉 Gatekeeper、SIP 或其他全域保護。管理政策禁止開啟時，請使用維護者提供的正式公證版。

## 第一次連線

到「設定 → 連線與 Agent」新增設備。填入遠端主機位址、SSH 使用者、連接埠與認證方式。選定這台 Mac 的工作目錄與 Agent。

- Codex 主機：已登入 Codex 0.160.0，填寫其 CLI 路徑或讓系統尋找。
- Claude 主機：原生 Claude Code 與 Node.js 已可執行，選擇官方帳號或 API 模式。
- 向主機擁有者核對首次出現的 SSH 主機金鑰指紋。
- 等待 Runtime 與 Mac 執行端實際連線，再送出工作。

遠端主機未準備好、帳號無額度或主機關機，都不是安裝本機額外軟體可以解決的問題。App 不內含共享帳號、API key 或免費模型。

## 本機權限

「電腦與工具 → macOS 系統權限」請求並檢查輔助使用與螢幕錄製。系統設定須授權目前 Applications 中的這個 App。macOS 如要求重新啟動 App，完成後再檢查。

「最高權限」控制 App 逐次核准行為，不能代替 macOS 系統權限，也不會免除系統密碼或帳號登入。未授予螢幕權限仍可使用不需要螢幕的功能。

## 內建工具與瀏覽器

新安裝預設使用內建 Computer Use。不必另外安裝 Open Computer Use。瀏覽器由安裝包提供，第一次使用不下載瀏覽器，不需要 Chrome 或 Safari 插件；它有獨立的登入狀態。

HTTP MCP 為選用功能，預設僅綁定 127.0.0.1。一般 AI 任務使用獨立工具通道，不必啟動 HTTP。要由其他電腦直接存取 HTTP，須明確選用已有的 Tailscale；本版不允許公開或一般 LAN 曝光。

## 常見問題

| 狀況 | 處理方式 |
| --- | --- |
| Runtime 握手逾時 | 確認遠端電腦開機、SSH 可达、登入資訊正確 |
| Codex 工具未就緒 | 使用與包內執行器配對的 Codex 0.160.0；未驗證版本可能被拒絕 |
| 權限顯示未授權 | 確認授權的是 Applications 中的目前版本，按更新狀態；更新未公證版可能需重新授權 |
| 內建元件遺失 | 重新下載並完整拖入 App，不需自行安裝 Node／MCP／瀏覽器 |
| 網站沒有登入 | 在 AgentBridge 的獨立瀏覽器中登入；不會讀取日常瀏覽器的 cookie |
| 模型無法回覆 | 檢查遠端帳號登入、模型資格、額度與網路，不要把工具連線成功視為模型可用 |

移除 App 不自動刪除聊天與檔案庫。若需刪除個人資料，先從 App 匯出需要保留的內容，再由使用者明確處理；發布檔不包含任何既有個人資料。

## 使用 HTTPS 連線（0.5.0）

如果 Mac 的網路無法連接 SSH，請讓 Runtime 擁有者使用附帶 Gateway 安裝包。到「設定 → 連線與 Agent」選 HTTPS，填公開網址、輸入一次性碼並配對，選擇工作資料夾與 Agent 後連線。兩條路都設定時可用「自動」。SSH 密碼不是 Relay 配對碼。

詳細步驟：[Gateway](../gateway/README.md)、[Tunnel](networking/CLOUDFLARE_TUNNEL.md)。公開網址、遠端 AI 登入與 macOS 系統權限需要你完成，不屬於額外下載本機執行相依套件。

## 0.5.5 聊天保存與長訊息

聊天改為保存在 App 使用者資料夾的 `chat-history/`，一般設定仍保存在原有本機設定。首次啟動會自動遷移舊聊天，成功保存後才移除舊儲存鍵；格式異常時保留原內容並顯示錯誤。回退到 0.5.0 不會直接讀取新聊天格式，回退前請先在新版匯出對話。關閉視窗會等候最後保存；若儲存失敗，請先匯出內容。

長訊息分段顯示，長對話可查看更早／後續訊息；完整文字仍可複製與匯出，顯示分段不會截斷保存的內容。


## 額度與回覆失敗時

| 顯示內容 | 意義與恢復方式 |
|---|---|
| Claude 登入狀態未確認 | 原生探測沒有回傳有效狀態，不等於已登出；按「更新 Runtime 狀態」再核對登入模式。 |
| 額度讀取器找不到 OAuth 憑證 | 確認 Runtime 的作業系統使用者、Claude 設定資料夾與官方／API 模式一致；API 登入不提供官方訂閱比例。 |
| 讀取鑰匙圈失敗 | 在 Runtime 解鎖鑰匙圈並允許原生憑證讀取；Mac App 更新也可能需要重新允許 macOS 保存的 SSH 憑證。 |
| 額度已用完 | 帳戶回報的真實限制；等重設後重試，不會由 App 繞過。 |
| 請求頻率限制／服務暫時故障 | 稍後重試；與訂閱額度耗盡分開，未提供不代表零。 |
| 遠端已找不到對話 | 原紀錄保留，下次送出以最近本機文字接續；附件需重新加，工具不自動重播。 |
| 上下文過長／模型不可用 | 按回報原因縮短新請求或選擇帳戶可用模型。 |
| 未提供具體失敗原因 | App 不猜測剩餘為零；保留紀錄與已收到的文字，供重新連線或手動重試。 |

Claude 額度的「更新剩餘用量」會重新偵測原生登入，再讀取新快照。更換設備或已識別的帳戶後，不沿用另一個帳戶的額度。訂閱查詢是官方未版本化介面；官方若限制該憑證查詢，仍可能無法提供比例。

若朋友已登入但額度仍顯示 `NO_OAUTH`，先確認 App 的 SSH 使用者、原生 Claude 執行檔與朋友登入的環境相同。Windows 原生與 WSL 的登入分開。連線設定新增「Claude 登入設定資料夾」，可指定原生 `CLAUDE_CONFIG_DIR` 的完整路徑；留白沿用原生預設。此欄位每台設備分別保存，工作資料夾不等於登入設定目錄。更改前先中斷 Claude Runtime，再連線並更新額度；不要把 OAuth Token 傳到 Mac 或貼到對話。

開啟 App 直接載入本機聊天紀錄，不必解鎖連線密碼。自動連線預設關閉，舊版開啟的設定也不會自動沿用；手動連線時若要讀取已保存的 SSH／HTTPS 憑證，macOS 仍可能要求解鎖鑰匙圈。
