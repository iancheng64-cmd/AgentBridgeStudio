## 尚未滿足的正式公開發布条件

1. 朋友完成原生登入後，正式 App 的 Claude 實際回覆、真實額度與長上下文壓縮。
2. 在另一台乾淨 Mac 上下載 DMG、首次啟動、macOS 權限、朋友 Runtime 及模型／工具完整任務；macOS 13 尚未實機驗收。此 DMG 只支援 Apple Silicon，沒有 Intel 產物。
3. Developer ID 簽章與 Apple 公證：本機沒有可用 Developer ID identity；目前為 ad-hoc，已提供 CI 資格設定入口但沒有冒稱公證成功。
4. 部署真正的公開 HTTPS/WSS 網址，測試跨網路、斷線與重新連線。SSH 與本機 TLS 測試不能替代此項。
管理員唯讀已於此 Mac 驗收成功；其他 Mac 的首次授權，以及 TCC／SIP 保護的路徑仍須依 OS 實際結果判定。

建議先以測試版交付，完成上述項目後再標為正式公開版。失敗資訊需分類回報；額度未提供不等於零，也不能把連線綠燈當成實際模型完成證據。

## 本次額外檢查

- 生產依賴 `npm audit --omit=dev`：目前回報 0 個已知漏洞；這不是完整安全稽核。
- 發布來源使用明確 allowlist、manifest 與 hash，排除使用者對話、憑證、個人設定、備份、node_modules 與測試暫存。
- DMG、包內工具與原始碼驗收結果記錄在 RELEASE_ACCEPTANCE.md；跨機、公證和真實帳戶條件另外列出。
- GitHub macos-14 runner 目前為 arm64，可匹配此 App；工作流程另做實際架構檢查。參考：[GitHub hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。

## 0.5.7 核心能力稽核

容錯搜尋、內容搜尋、衝突編輯、程序生命週期、內建 Node、任務版本與隔離、網頁大小／URL 檢查及 MCP 資源／提示均有真實 loopback MCP 測試。正式包內驗收另外執行「建立檔案→修改→搜尋→使用包內 Node 測試→保存進度→重連讀回→網頁讀取」，不依賴外部 Node 或瀏覽器下載。

GitNexus 等專案指定的第三方能力不列為內建。Agent 會查詢實際工具清單及讀取專案規則；若必要工具未接通，不能冒充已做影響分析。外部 OAuth MCP 仍須使用者完成該服務登入；讀到設定不等於已接通。
